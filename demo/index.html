🏛️ Stotra Manjari Application Architecture

Design Philosophy & Layered Architecture

Stotra Manjari is designed as a sacred digital temple for reading and chanting Vedic hymns. The architecture balances pure visual aesthetics (cinematic gold accents, aged parchment sepia, deep obsidian dark) with robust engineering:

  • Zero-Dependency Static Client: Can be served entirely from any static CDN or GitHub Pages with instantaneous loading.
  • Offline-First Resilience: Full PWA manifest and Service Worker pre-caching all scripts, fonts, and data assets.
  • Declarative State Synchronization: React / Modern JS architecture synchronizing typography, script rendering, and audio karaoke timestamps.

1. Typography & Readability Architecture

Indic languages require specialized Unicode typography rules to prevent conjunct clipping, improper vowel placement, or awkward line wrapping. 

/* Dynamic font scaling via CSS custom properties */
:root {
  --reader-font-size: 1.35rem; /* Dynamic: scaled via A+/A- buttons */
  --reader-line-height: 1.95;  /* Tuned for Indic vowel diacritics */
  --font-telugu: 'Noto Sans Telugu', sans-serif;
  --font-devanagari: 'Noto Serif Devanagari', serif;
}

/* Theme Switching with CSS variables and data-theme */
[data-theme="sepia"] {
  --bg-base: #f5efe3; /* Palm-leaf manuscript parchment */
  --text-primary: #2a2116; /* Sandalwood dark amber */
  --accent: #b56b14;
}

2. Multi-Script Transliteration & Word Breakdown

Uses Brahmic phonetic mapping. Because Sanskrit in Indian scripts shares identical phonetic phonemes, transliteration from Telugu to Devanagari, Kannada, Tamil, or IAST Roman happens client-side with zero latency: 

// Instantaneous Transliteration
const textDevanagari = Sanscript.t(verseTelugu, 'telugu', 'devanagari');
const textIAST = Sanscript.t(verseTelugu, 'telugu', 'iast');

// Padaccheda (Word-by-word) Schema
{

  meaning: 'Holding the delicious sweet modaka in hand with pure joy'

3. Web Audio API Synthesis & Karaoke Sync

Instead of relying on large MP3 files that fail to load offline, the demo employs a Web Audio API synthesizer generating a polyphonic Tanpura drone at 136.1Hz (the sacred Om pitch), resonant temple bell chimes, and Vedic chant cadences: 

// Tanpura Drone Fundamental Pitch (136.1 Hz)
const baseSa = 136.1; // C#3
osc.frequency.setValueAtTime(baseSa, audioCtx.currentTime);

// Karaoke Timestamp Synchronization
audioEngine.onVerseChange((activeIdx) => {
  document.querySelectorAll('.verse-card')[activeIdx].classList.add('active');
  card.scrollIntoView({ behavior: 'smooth', block: 'center' });
});

5. GitHub Actions & GitHub Pages Deployment

This demo is structured with relative paths (./) ensuring full compatibility with GitHub Pages and GitHub Actions workflows: 

# .github/workflows/deploy.yml
name: Deploy Static Site to GitHub Pages
on:
  push:
    branches: [ master ]
permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci
      - run: npm run build
      # The demo directory is uploaded alongside static exports
      - uses: actions/upload-pages-artifact@v3
        with:
          path: ./out
      - uses: actions/deploy-pages@v4
